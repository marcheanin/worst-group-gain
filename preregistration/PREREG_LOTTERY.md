# Предрегистрация: лотерея валидации (сожаление отбора) на toxlang

Написано 2026-09-23, пока идёт оценка кандидатов на тесте. Оценка запущена раньше этого
текста, но ни одного предсказания кандидата из архива к моменту записи не прочитано: скрипт
анализа (`scripts/archive_regret.py`) пишется после этого файла. Хеш файла — в
`PREREG_HASH_LOTTERY.txt`.

## Вопрос

Выбрасывает ли поиск сильные промпты из-за шумной валидации? Каждый из 12 живых прогонов
(4 метода × 3 сида, протокол `hard_min`) по ходу работы оценил 7–20 кандидатов на dev
(подвыборка 400/432/500 строк или полный dev 900 строк) и выбрал финал по dev. Если отбор по dev
ненадёжен, в архиве прогона могут лежать кандидаты, которые на независимых данных лучше финала.

## Данные

- Кандидаты: 138 уникальных текстов из `results/S15_toxlang_loop/seed*/*/archive.json`
  (152 оценки, 12 прогонов). Сборка — `scripts/build_s15_lottery.py`, карта прогонов —
  `results/S15_toxlang_matrix/archive_map.json`.
- Тест: первые 1000 строк `truth_tox` (перемешанное множество, префикс стратифицирован),
  скорер gemma-3-12b, тот же конфиг, что у финалов. Сид и финалы берутся из уже посчитанных
  предсказаний на 3000 строк — первые 1000 строк те же самые.
- Строки, где хоть один кандидат дал INVALID, исключаются для всех (парность бутстрепа).

## Статистики (заданы до результатов)

Основная метрика — `hard_min` (минимум GBA по шести языкам), как в протоколе прогонов.
Вторичные — `mean_gba` и `worst_class`, чтобы увидеть, специфична ли лотерея для `hard_min`.

1. **Наивное сожаление** прогона r: R_r = max_c T(c) − T(финал_r) по кандидатам архива r.
   Оно смещено вверх проклятием победителя на тесте и само по себе ничего не доказывает.
2. **Сожаление с поправкой на отбор**: бутстреп внутри ячеек язык × метка (4000 повторов,
   общие индексы). M* = max_c [(T*_c − T*_f) − (T_c − T_f)]; p_r = доля повторов с M* ≥ R_r.
   Поправка Холма по 12 прогонам.
3. **Кросс-фит сожаление** (несмещённая оценка выигрыша от «оракульного» отбора): тест делится
   пополам стратифицированно по ячейкам; лучший кандидат выбирается на одной половине,
   сравнивается с финалом на другой; обе стороны, 200 случайных разбиений, среднее.
4. **Согласие dev и теста**: ранговая корреляция Спирмена между оценкой на dev и `hard_min`
   на тесте — отдельно для кандидатов, оценённых на полном dev, и для оценённых только на
   подвыборке.
5. **Где теряются кандидаты**: из кандидатов, превзошедших финал на тесте сильнее порога C95,
   сколько отсеяны на подвыборке и сколько проиграли на полном dev.

## Гипотезы и правила решения

- **H-L1 (лотерея существует).** Подтверждена, если хотя бы в одном из 12 прогонов сожаление с
  поправкой на отбор значимо после Холма (α = 0,05). Иначе — не подтверждена.
- **H-L2 (лотерея существенна в среднем).** Подтверждена, если среднее кросс-фит сожаление по
  12 прогонам ≥ 0,02 по `hard_min`. Порог 0,02 выбран заранее как величина порядка типичного
  выигрыша метода над сидом на этом стенде. От 0 до 0,02 — «промежуточно», ≤ 0 — опровергнута.

## Мой прогноз (для честности — записан до данных)

Кандидаты внутри прогона — в основном мелкие правки одного сида, настоящие различия между ними
малы. Ожидаю: наивное сожаление в среднем 0,03–0,05 (почти целиком проклятие победителя);
значимых после Холма прогонов 0–2; кросс-фит сожаление около нуля (|среднее| < 0,01);
корреляция dev–тест на полном dev умеренная (0,3–0,5), на подвыборке ниже. То есть прогноз —
H-L1 скорее не подтвердится, H-L2 будет опровергнута. Если выйдет иначе, это и будет находкой.

## Что считается результатом в обе стороны

- Если лотерея есть: отбор по dev на 900 строк не отличает сильные промпты от слабых, и часть
  «проигравших» методов проиграла из-за отбора, а не из-за поиска. Это усиливает основной тезис
  статьи о недостаточном размере измерения и добавляет к нему этап отбора.
- Если лотереи нет: поиск не теряет сильных промптов — архив в среднем не лучше финала; слабые
  результаты методов означают, что поиск просто не находит улучшений, которые отличимы от шума.
